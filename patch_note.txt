===== V-1.1.0.4_dev =====

- Fix network id behavior in the Python interface. Default init network id is zero, meaning that calling init twice without specifying id
  will destroy and recreate a network with id zero. However, if a network_id is specified, it now sets a global_current_network_id variable.
  With this change, all API functions called after a given network init with no network_id specified as argument will automatically apply to
  the last initialized network (and not to the network_id 0 as before).
- Change in API interface. Following popular request, most function arguments that previously required pre-typed numpy arrays (int or float32)
  now also support lists and tuples; e.g., cnn.conv(f_size=i_ar([3,3])) can now be replaced with cnn.conv(f_size=[3,3]) or cnn.conv(f_size=(3,3)).
  Previous argument format is still supported for backward compatibility. Data arrays provided as input still need to be provided as explicitly
  typed float32 numpy arrays. Also, all layers supporting a "prev_layer" argument or similar now work as absolute or relative.
  Some interface functions now also return a layer id (e.g., cnn.load() returns the last loaded layer id).
  Overall, many interface functions have been patched to properly increment and decrement python variables, fixing some very long training crashes.
- Rework input design. Add a new INPUT layer type, created with the cnn.input() interface function, with one mandatory keyword "nb_features", 
  and one optional argument "spatial_shape" (plus classical silent and network arguments) and returning the layer id. 
  The corresponding arguments are therefore removed from the cnn.init() function.
  A network can now have an arbitraty number of INPUT type layers. These layers are added to the network structure as classical layers and can
  therefore be referenced by their absolute or relative id by other layers.
  To follow this change, the cnn.create_dataset() function now takes a list (or tuple, or numpy array of objects) of 2D data arrays as argument
  for both "input" and "target" keywords (target remains optional for the TEST dataset, and only the first target data array will be used for now). 
  Each data array must match the dimension of its corresponding input layer in order of declaration (checked when calling the train function).
  These changes enable the construction of complex multi-branch network architectures (class-conditioned networks, multimodal networks, etc.). 
- Rework norm layer to AdaGN (Adaptive Group Norm). Normalization layers now declare an internal DENSE layer (hidden from the global network structure)
  that performs a projection from a condition input layer to the gamma and beta values. If no condition input layer is provided, the projection takes
  a constant hidden input instead (stored in the network structure), reproducing the classical GN normalization. 
  The stored NORM layer parameters now correspond to the projection layer's weight matrix rather than the gamma and beta values directly.
  Also, scaling is now performed with (1+gamma) instead of just gamma, allowing the projection layer to learn a deviation from identity.
  Interface should be backward-compatible (except for gamma_init renamed to gamma_start). A new "cond_layer" argument can be used to specify
  the absolute or relative id of the layer to use as condition input (leave undeclared for constant input).
  This change allows the creation of efficiently conditioned models (mostly for generative models) or the merging of input branches of different kinds.
  Note that this change only applies to the NORM layer type for now. GRN layers still learn non-conditioned gamma and beta parameters directly.
- Remove bias auto propagation through weight matrix pivot (replaced with forward and backprop time bias setting to allow dense layer branching).
  The pivot column is preserved in the current implementation of dense weight matrices, even though it is now only filled with zeros, as it allows
  to automatically create outputs that accommodate an extra output column used to store the bias input for subsequent layers. 
  Also fix remaining bugs related to leaking gradient propagation to the pivot vector.
- Update MERGE layer to support FLAT format (dense) layers merging.
- Change the saving format of the "opt_step" parameter from the Adam optimizer to an explicit 6-bit unsigned integer to prevent overflow
  and ensure compatibility between 32-bit and 64-bit systems. Some other saved arguments should follow.
- Update MERGE to support input layers as well.
- Fix an error in freeing GRN layers

===== V-1.1.0.3_dev =====

- Fix layer skipping when loading a save state in binary format.
- Fix an error in dense-to-conv connect introduced by the last FLAT/SPATIAL refactor.
- Fix an error adding a TC_padding of 8 when unnecessary (this will marginally reduce memory footprint and improve compute efficiency).
- Implement per-group parameter sharing in grouped convolution. As an example, from an input with 32 channels
  cnn.conv(f_size=i_ar([1,1]), nb_filters=2, nb_groups=4, group_param_sharing=1)
  will decompose the input channels into 4 groups of 8 channels and each group will be convolved with the same 2 filters of size 1x1x1x8,
  leading to an output with nb_filters*nb_groups (here 8) activation maps. This contrasts with classical grouped convolution where each
  group gets independent filters.
  Note: when group_param_sharing=0, the nb_filters argument must be the total number of output filters (will be split amongst groups), 
  while when group_param_sharing=1, the nb_filters argument is the number of filters per group, scaled in output by the number of groups.
  Therefore, "nb_filters" always represents the number of learnable parameters in the layer (multiplied by the kernel size).
- Add no-deprecated-gpu-targets to cuda compilation to prevent errors when compiling for VOLTA on cuda 12.8/12.9 (latest supported version)
- Fix an issue in perf eval that would unfairly add latency of the first-ever program kernel launch to the first layer forward time.
- Move previous layer logic from the python interface to the C code for each layer. The new formulation allows for expressing prev_ids as relative to
  the current layer, like for merge layer arguments. The saved prev_id for each layer is now expressed as relative. This increase the chances that
  subparts of a given model can be loaded independently (for example, the decoder part from a U-net that contains skip connections).
- Rework MERGE layer to allow > 2 previous layers. The new version takes an array of relative (negative only) or absolute layer ids as an argument.
  This rework should improve code clarity and reduces memory footprint when merging more than two layers (previously achieved by stacking merge layers).
- Rework of the YOLO-CIANNA assignment phase. This change aims at simplifying the code itself, improving performances, and also fixing some unexpected
  behavior present in the previous implementation. For a detailed view of the new approach, look at the code itself. In summary:
  * Random prior association is now decided per cell elements and affects all units in the cell (used at startup or at a small rate). 
    All other association processes are ignored in that case.
  * All elements that restrict association are now affecting directly the association matrix (through masking of the distance_to_prior matrix).
  * Restrict to the smallest prior is now applied first and is considered a priority compared to other association refinments.
  * Random best prior association is now considered as a special case of setting strict_box_size_association = 1 on the current cell.
  * Prediction-awase association then takes place on the masked IoU and dist_to_prior matrices. Association ordering is based on the IoU when above 
    low_IoU_best_box_assoc and based on dist_to_prior otherwise. When matching based on dist_to_prior, multiple identical priors are discriminated based 
    on the predicted IoU.
    One consequence of this change is that, in contrast with setting strict_box_size_association = 1 which would prevent association if the best theoretical
    prior is already set to another target, the new low_IoU_best_box_assoc simply search for the best remaining prior available / authorized.
  * Difficult flag status is checked for each association pair and IoU / Obj limits are checked before assignement validation.
  * A new alternative association priority has been added (opt-in for the moment) based on minimising regret of assignement. The current best match
    is not selected based on the highest IoU score anymore, but on the highest difference between the best and second best associaiton for each box.
    This approach allows for selecting better "global" solution instead of always affecting "best first" regardless of the quality of the other predictions.

===== V-1.1.0.2_dev =====

- Change default activation of Conv and Dense to LIN instead of RELU
- Add tunable classification label smooting to the YOLO loss. Using an alpha smoothing scaling, negative class has a target of alpha/nb_class, 
  while positive class has a target of (1-alpha) + alpha/nb_class.
- Change in saving format to include previous layer id just after the layer type. This change allows to save and load architecture with more
  advanced branching that could already be build with CIANNA but impossible to save and load.
- Fix a save file loading error that was happening when loading a YOLO activated conv layer using the ASCII save format.

===== V-1.1.0.1_dev =====

Recreate dev branch from the V-1.1.0_exp branch to ensure consistency.

- Add manual initial setup of NORM layer gamma (std) value. Setting gamma to 0 in the last norm layer of a residual block ensure initial identity operation.
- The NORM layer is changed to have one gamma and beta parameter per output channel (instead of one per group). This is done do better align with classical
  layer norm description and restor expresivite at the normalization output. We also remove the set_off parameter as it has not proven usefull until now.
- Fix an error introduced in dense to conv linking during last refactor. Also decompose dense to conv forward and backward functions better to ensure that
  gradient is properly accumulated to comply with layer merging expectation.
- Add a new Global Response Normalization (GRN) layer following ConvNext V2 (Woo et al. 2023) definition. Each channel is cross-channel L2 normalized. 
  Each channel is then scaled with learnable parameters like a in NORM layer (gamma*x + beta). The GRN is also redisual by default, adding the original
  input to the renormalized-scaled output (this is user-controled, so it can be de-activated with a dedicated keyword).
- All normalization layers (NORM and GRN) CUDA implementation now relies on end-to-end GPU compute. Previous implementation was doing some reduction
  steps on the host CPU and the CPU version of the optimizer was used. This was causing unrequired host-device synchronization hurting latency.
- Fix BLAS linking in the latest Cmake install so it now support a wider variety of BLAS implementation. As a side effect, this allows the installer
  to use the native BLAS on Mac OS (tested on an M2 equiped device).
- Get minor fixes from stable branch (better compute backend fallback message, at compute time backend selection in main and new test mode main,
  fix all python function returns to prevent long train run crash)

===== V-1.1.0_dev =====

Branch and empty the patch for the new DEV branch.
Initial state of the branch is based on Stable V-1.0.1.1 (commit a24c040)
-> Final state used to create the V-1.1.0_exp branch.

- Backprop now accumulates the gradient in the previous layer instead of setting its value. All layers set their own gradient to zero at inference time.
  This change aims at allowing complex layer branching (e.g., split and merge layers).
  NOTE: We should accommodate a way to manually set the gradient values to zero for all layers in order to decorrelate it from an inference step.
  (This could help for GAN-like network structures).
- Generalize the LRN layer to CPU computation (identical for BLAS and NAIV backends)
- Remove the input bias setting for more clarity. Bias default value is now defined based on the activation function unless specified as a layer argument
  (affecting the input of this layer). For SPATIAL layers, bias is always set by im2col, and for FLAT layers (dense specifically), the input bias is
  set by the forward function, while all subsequent dense layers use the weight matrix pivot trick.
- Layer and activation data structure rework (simplification):
  - All non-specific activation variables have been removed. Replacement size-related variables are now present in the layer structure
    and can be used for different purposes by each layer/activation type. All functions have been updated accordingly.
  - Layers are now characterized by their “output format”, either SPATIAL (CONV, POOL), or FLAT (DENSE). Transformation layers that can be applied to both
    formats (NORM, LRN, MERGE) now inherit their format from the previous layer. This change allows to simplify complex architecture structure
    dependencies that were reflected by complex branched conditions in various places in the code.
  - While the logic has been updated, the NORM and LRN layers still need to be adapted to handle FLAT-formatted layer outputs.
- Fix an error in Linear, ReLU, and Logistic activation for dense layers that was erasing the bias value, setting a zero value instead.
  This was only present when two dense layers were stacked; adding a single dense layer at the end of an otherwise fully-conv network worked as intended.
  This error is likely present in V-1.0 but will not be retroactively patched, as it would break the deterministic behavior of existing trained models.
  The fix is only applied for V-1.1+, which is already expected to break backward save compatibility to some extent.
- Rework fixed optimizer construction for a modular multi-optimizer approach (in optimizers.c and cuda_optimizers.cu). An optimizer and its configuration
  can now be selected at runtime through an argument in the init function. Currently supported optimizers are SGD with momentum, RMSprop, and ADAM.
  While the optimizer itself cannot be changed after network initialization, its configuration can be updated dynamically (e.g., momentum value for SGD).
  Learning rate and weight decay remain general parameters set when the train function is called and can therefore be scheduled finely.
  Also, the optimizer is now applied to all learnable parameters via a unified function, including normalization layer scaling and shift values.
- Fix an error in weight decay that was not affecting all learnable parameters equally. Now, weight decay is done in each optimizer and affects only the weights in
  dense and conv layers (ignoring norm layers) and is not applied to the bias weight (as initially intended).
- Add Weights Exponential Moving Average for all learnable parameters directly at the end of each optimizer (same kernel launch). Shadow EMA weights are
  updated during training, while all inference steps (inference over the validation dataset during training or separate inference over the test set) use
  the EMA weights instead of regular weights. WEMA usage can be specified at init time (for allocation), while the WEMA rate can be set (and updated)
  through the train function. Running weights can be replaced by the EMA weights periodically using a wema_replace_every keyword in the train function.
- Add an option to decouple weight decay from the optimizer computation (while still performing it in the optimizer functions). This typically allows adamW.
- Fix an error in the conv NAIV weight gradient computation that came from a previous code refactoring (does not affect V-1.0).
- Add a new layer type, MERGE, for all compute backends. A merge layer takes absolute or relative ids for two input layers as arguments and can either be
  of type ADD or CONCAT. ADD type merge layers sum two layers output element-wise and require the two input layers to have the exact same shape,
  while CONCAT merge will append features from the two layers in a new output and only require the spatial shape to be identical.
  For now, merge can only take “SPATIAL” output type layers as input (CONV, POOL, NORM), but we plan to generalize them to FLAT layers as well.
- Rework the saving system to store the optimizer and EMA states for proper training restart. The regular save format is now based on running or EMA weights if use_wema is set to 1
  (EMA weights are already the ones used on the validation and test dataset).
  An optim save file stores regular weights, ema_weights if use_wema is 1, and the optimizer variables (e.g., for Adam, the optimizer state, the first and second moments,
  and second moment max value if ams_grad is set to 1). The train function exposes this capability through the save_optim_every optional argument,
  while the save function allows specifying a save_optim_state optional argument. By default, optim save files are stored in a directory named optim_save.
  When loading a save file, the format (regular or optim save) is determined automatically. If an optim save file is loaded while there is
  no layer in the model yet, then the full optimizer configuration is replaced by the one loaded from the file. In contrast, if at least one layer already exists,
  the loading scheme will only update possible optimizer values (e.g, can’t change the choice of optimizer, the activation of wema, or of ams_grad for ADAM).
- Major rework of the convolutional layer. This change was motivated by the addition of depth-wise convolution. Instead of adding a special case, the whole convolution
  has instead been revamped as a general case depth-grouped convolution. Regular convolution and depth-wise convolution are now special cases of this general implementation, 
  with either nb_group = 1 or nb_group = nb_input_channels. The interface remains identical, just adding the number of groups as an extra optional argument.
  Internally, the grouped convolution is decomposed into subproblems, each corresponding to a convolution on a subset of nb_input_channels/nb_group input features using
  nb_output_channels/nb_group filters. All data arrays related to the convolution operation are now decomposed into chunks, each representing a sub-convolution.
  Regarding computation, for both CPU implementations, we simply loop over the subproblems, whereas in CUDA, we use the cublasGemmStridedBatchedEx function.
  All other kernels have also been rewritten accordingly (e.g., im2col and rotate_filters).
- Fix a bug related to OpenMP. On some systems, not setting OMP_NUM_THREADS manually causes strong performance issues for both OpenBLAS gemm and our custom functions.
  Now, if OMP_NUM_THREADS = OMP_MAX_THREADS at startup (likely not manually set), we automatically set OMP_NUM_THREADS = OMP_MAX_THREADS/2, fixing the issue for most systems.
  The same check is done independantly for OpenBLAS in case a version no compiled with OpenMP is used.
- Datasets no longer require a target array to be declared. This change specifically targets the TEST dataset that is used for inference, so no zero-filled target array is required.
  Checks have been added at several places to verify that operations on a given dataset are authorized without a target array (e.g., training now returns an error if provided with
  a train dataset without target labels). The forward function now defaults to “no_error=1” to follow this change.
- The forward model function now returns a NumpyArray containing all the predictions for the current TEST dataset. Saving still defaults to 1, so the model also saves a file 
  with the result. This change aims to speed up models that require frequent inference, like DDPMs that require many recursive forward passes to generate the final image.
- Removed the appended 0 to output prediction and saved values when the last layer is of type FLAT. This zero, resulting from the automatic dense layer bias propagation, is
  still present internally, but is now skipped when writing to file and in the output array.
- Fix an error in the CPU version of the YOLO_error computation (only affect error display, not training).
- Fix an error in free layer that was causing crash when freeing networks.
- Also include the new makefile installation from the stable version (updated for the experimental version)
